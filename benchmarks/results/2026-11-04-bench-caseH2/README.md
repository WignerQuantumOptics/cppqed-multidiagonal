# 2026-11-04, reference machine: case H, the distance between the arrays

Measured before `benchmarks/run.sh` existed, with the one-off script [`caseH2.sh`](caseH2.sh), kept here as it was on the machine.

- **What:** `kernels` case H (the distance between `psi` and `dpsidt` out of cache, on huge pages and on 4 KB pages), five processes, pinned to core 1.
- **Source:** the library as in c346b8a, with case H as it was committed that afternoon in d29ec7e, rebuilt in the build directory of the session before. Release, `-march=native`.
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler and Eigen versions; the page gives GCC 16.2.1 and Eigen 5.0.1 for the machine at the time.
- **Pages:** case H places its arrays itself and asks for huge pages or 4 KB pages per case; the process as a whole ran as the system handed out pages, hence `thp` in the file names.
- **Quoted in `performance.md`:** the table of "Distance on huge pages".

The files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged:

| as the script wrote it | here |
|---|---|
| `kdef.H.N.csv` | `caseH/kernels.H-thp-rN.csv` |
| `kdef.H.N.err` | `caseH/kernels.H-thp-rN.err` |
| `log` | `log` |

`REPORT.md` is generated by `benchmarks/reduce.py report`.
