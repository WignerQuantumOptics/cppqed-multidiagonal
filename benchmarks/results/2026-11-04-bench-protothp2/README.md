# 2026-11-04, reference machine: an allocator in `StorageType`, second prototype

Measured before `benchmarks/run.sh` existed, with the one-off script [`protothp2.sh`](protothp2.sh), kept here as it was on the machine.

- **What:** the same workloads again, in three modes: the unchanged code on huge pages and on 4 KB pages, and the second prototype on huge pages, whose `StorageType` starts each large array at one of 16 positions within a page, in turn. Five rounds alternating, pinned to core 1.
- **Source:** `base` is the library at 14254a1 (the build of `2026-11-04-bench-remeasure`) and C++QED 0a0efb12 with Eigen 3.4.0; `proto2` is the same with [`proto2-library.patch`](proto2-library.patch) applied to the library (the patch is against the source of `base`).
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler version; the page gives GCC 16.2.1 for the machine at the time, and Eigen 5.0.1, which the library's benchmarks used.
- **Quoted in `performance.md`:** the prototype is the "allocator in `StorageType`" of "Distance on huge pages"; the figures quoted for it there are from `2026-11-05-bench-allocs`, which measured it again beside jemalloc and tcmalloc.
- **`times`:** one line per run of `jc_qjmc`: mode, mode cutoff, round, wall time in milliseconds. The trajectories that the runs wrote are not kept here; they are C++QED's output, not this library's.
- **`alloc.proto2.log`:** the large allocations of one run of `jc_qjmc` built against the prototype.

The benchmarks' files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged. The script's mode on 4 KB pages (`nothp`) ran the binaries of `base`, so its files are those of `base` on `4k`:
