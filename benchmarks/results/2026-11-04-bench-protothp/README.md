# 2026-11-04, reference machine: a padding allocator in `StorageType`, first prototype

Measured before `benchmarks/run.sh` existed, with the one-off script [`protothp.sh`](protothp.sh), kept here as it was on the machine.

- **What:** the same workloads as the session before, in three modes: the unchanged code on huge pages and on 4 KB pages, and a prototype on huge pages whose `StorageType` pads large allocations by 1 KiB. Five rounds alternating, pinned to core 1.
- **Source:** `base` is the library at 14254a1 (the build of `2026-11-04-bench-remeasure`) and C++QED 0a0efb12 with Eigen 3.4.0; `proto` is the same with [`proto-library.patch`](proto-library.patch) applied to the library (the patch is against the source of `base`).
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler version; the page gives GCC 16.2.1 for the machine at the time, and Eigen 5.0.1, which the library's benchmarks used.
- **Quoted in `performance.md`:** not by its figures; a step toward the allocator of `2026-11-04-bench-protothp2` ([#26](https://github.com/WignerQuantumOptics/cppqed-multidiagonal/issues/26)).
- **`times`:** one line per run of `jc_qjmc`: mode, mode cutoff, round, wall time in milliseconds. The trajectories that the runs wrote are not kept here; they are C++QED's output, not this library's.
- **`alloc.proto.log`:** the large allocations of one run of `jc_qjmc` built against the prototype.

The benchmarks' files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged. The script's mode on 4 KB pages (`nothp`) ran the binaries of `base`, so its files are those of `base` on `4k`:
