# 2026-11-04, reference machine: cases F and H in one process

Measured before `benchmarks/run.sh` existed, with the one-off script [`caseH.sh`](caseH.sh), kept here as it was on the machine.

- **What:** `kernels` cases F and H in one process, F first so that its arrays are allocated as in the session of case F; five processes, pinned to core 1.
- **Source:** the library as in c346b8a (v0.4.1), with the first version of case H in `kernels.cc`, which set only the offset of the arrays within a page. Release, `-march=native`.
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler and Eigen versions; the page gives GCC 16.2.1 and Eigen 5.0.1 for the machine at the time.
- **Pages:** as the system handed them out, which on this machine means transparent huge pages for all large arrays; hence `thp` in the file names.
- **Quoted in `performance.md`:** the first paragraph of "Distance on huge pages". The `.err` files carry, for case F, the distance between `psi` and `dpsidt` modulo 4096.

The files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged:

| as the script wrote it | here |
|---|---|
| `kdef.FH.N.csv` | `caseH/kernels.F+H-thp-rN.csv` |
| `kdef.FH.N.err` | `caseH/kernels.F+H-thp-rN.err` |
| `log` | `log` |

`REPORT.md` is generated by `benchmarks/reduce.py report`.
