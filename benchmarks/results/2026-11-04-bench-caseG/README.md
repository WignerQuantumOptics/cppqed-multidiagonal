# 2026-11-04, reference machine: case G, the placement scan

Measured before `benchmarks/run.sh` existed, with the one-off script [`caseG.sh`](caseG.sh), kept here as it was on the machine.

- **What:** `kernels` case G (`psi` at every 16-byte offset of a page relative to `dpsidt`, both loop shapes), two processes, pinned to core 1.
- **Source:** the library as in c346b8a, with case G in `kernels.cc`, committed right after the session as f05db34. Release, `-march=native`.
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler and Eigen versions; the page gives GCC 16.2.1 and Eigen 5.0.1 for the machine at the time.
- **Pages:** as the system handed them out, which on this machine means transparent huge pages for all large arrays; hence `thp` in the file names.
- **The `.err` files** hold the summary per scan that case G writes to the standard error; the script had named them `G.N.summary`.
- **Quoted in `performance.md`:** the table of "Placement of the arrays", which is from the first of the two processes.

The files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged:

| as the script wrote it | here |
|---|---|
| `G.N.csv` | `caseG/kernels.G-thp-rN.csv` |
| `G.N.summary` | `caseG/kernels.G-thp-rN.err` |
| `log` | `log` |

`REPORT.md` is generated by `benchmarks/reduce.py report`.
