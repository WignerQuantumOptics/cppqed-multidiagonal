# 2026-11-07, reference machine: case I

Measured before `benchmarks/run.sh` existed, with the one-off script [`caseI2.sh`](caseI2.sh), kept here as it was on the machine.

- **What:** `kernels` case I (the crossover of the two loop shapes for contiguous slices, over 15 placements within a page, in states of 2¹² to 2²⁰ amplitudes), three processes, pinned to core 1.
- **Source:** the working tree of that morning for [#27](https://github.com/WignerQuantumOptics/cppqed-multidiagonal/issues/27), committed the same day as 78785f0. Release, `-march=native`.
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler and Eigen versions; the page gives GCC 16.2.1 and Eigen 5.0.1 for the machine at the time.
- **Pages:** case I keeps itself on 4 KB pages; the process was started as the system hands out pages, hence `thp` in the file names.
- **Quoted in `performance.md`:** the table of "Contiguous slices of a state larger than cache". The `.err` files hold the median and the worst over the placements per configuration, which the table is made of.

The files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged:

| as the script wrote it | here |
|---|---|
| `I.N.csv` | `caseI/kernels.I-thp-rN.csv` |
| `I.N.err` | `caseI/kernels.I-thp-rN.err` |
| `log` | `log` |

`REPORT.md` is generated by `benchmarks/reduce.py report`.
