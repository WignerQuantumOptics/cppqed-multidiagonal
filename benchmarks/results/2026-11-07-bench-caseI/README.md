# 2026-11-07, reference machine: case I, first run

Measured before `benchmarks/run.sh` existed, with the one-off script [`caseI.sh`](caseI.sh), kept here as it was on the machine.

- **What:** `kernels` case I (the crossover of the two loop shapes for contiguous slices, over 15 placements within a page), three processes, pinned to core 1.
- **Source:** the working tree of that morning for [#27](https://github.com/WignerQuantumOptics/cppqed-multidiagonal/issues/27), with case I for two state sizes. Release, `-march=native`.
- **Machine:** the reference machine of [`performance.md`](../../performance.md), "Setup". Its state at the start and at the end is in `log`. The script did not record the compiler and Eigen versions; the page gives GCC 16.2.1 and Eigen 5.0.1 for the machine at the time.
- **Pages:** case I keeps itself on 4 KB pages; the process was started as the system hands out pages, hence `thp` in the file names.
- **Quoted in `performance.md`:** not directly. The table of "Contiguous slices of a state larger than cache" is from the run five minutes later, `2026-11-07-bench-caseI2`, which has five state sizes.

The files were renamed to the layout of `run.sh`, so that `benchmarks/reduce.py` reads them; their contents are unchanged:
